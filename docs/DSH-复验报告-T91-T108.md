## 5. 新发现 F-8：checkbox 参数布尔化导致语义错误数据 —— **P0 候选** 🔴

**证据链**（全部实测）：

```
录制原始动作:  {type:'checkbox', label:'parts', value:'SCREEN'}   ← 配件=屏幕
draft 参数化:  parts: boolean（params.ts:182 硬编码 checkbox→boolean，丢弃 value）
回放传参:      parts: true
服务端落库:    {"parts":["true"]}                                  ← 配件="true"（不存在的东西）
```

- 用户操作「申请更换**屏幕**」，实际写入「更换 **true**」——**执行成功、无报错、业务数据错误**，完全命中 P0 定义
- 服务端原文：`{"id":"RC-0016","deviceType":"MONITOR","urgency":"CRITICAL","desc":"TA2 连续第5轮：显示器花屏","parts":["true"],...}`
- 复现：`node tmp/ta2-replay-verify.mjs`（parts:true 传参）后 `curl /api/records`
- 归类：**DOM / Analyzer**（params.ts:182 通用逻辑，非业务特判缺失）
- 缓解因素：draft 中 parts 参数带 TODO 复核标记——**但「boolean」类型本身就无法表达配件选择**，人工复核在不改类型的前提下无解（只能 enum 重写——即测试者本轮做的修正）
- **修复方向**（供 Codex，非业务特判）：checkbox 参数类型应为「值枚举」（controlSemantics.value 即证据），boolean 仅适用于「勾/不勾同一值」场景

**边界验证**：测试者人工把 parts 改为 enum 后，回放写入 `parts:["SCREEN"]`——正确数据。即**缺陷仅在分析器的类型推断，回放链路本身能正确传递枚举值**。

## 6. 新发现 F-9：postcondition 匹配器不支持数组值 —— **P2** ⚠

- `matchesWhere`（engine.ts:476-481）逐键 `String(candidate[key]) === expected`——服务端 form 序列化的同名字段多值（`parts=SCREEN&parts=BATTERY` → `parts:["SCREEN","BATTERY"]`）时 `String(["SCREEN"])` = `"SCREEN"`（单元素数组恰好相等！）但多元素数组 `[..]` 恒不匹配；且 label→value 映射（屏幕→SCREEN）也需人工对齐
- **标量键路径验证 PASS**：where 只含标量（deviceType/urgency）时 `ok=true, s7=confirmed_success, found=true, 增量恰好1`——**302→opaque→postcondition 收敛链完整工作**
- 归类：Replay（匹配器通用性）
