# T-76 会话常驻进程报告

## 结论

T-76 放行。CLI 已提供 `dsh session start/status/stop`，daemon 持有 persistent context，录制与回放通过 CDP 附着同一 context。daemon 只执行 entry 导航、会话探测和失效时前台提示，不执行登录或业务动作。

## 策略行为

| `sessionHolding.strategy` | 无现存会话时行为 |
|---|---|
| `daemon` | 拒绝执行并提示先启动 session |
| `probe-only` | 启动独立 persistent context |
| `storage-state` | 明确报告 T-78 未启用，不隐式降级 |

录制与回放只接受 `active` daemon；`starting` 和 `invalid` 均拒绝附着。状态文件对应 PID 不存活时，`session status` 报告“无会话”。

## 契约与 doctor

`EntrySchema.sessionHolding` 已包含：

- `strategy`，默认 `daemon`
- `probeIntervalMs`，默认 30000
- `stateTtlMs`，默认 1800000
- `cookieKind`，默认 `unknown`

`dsh doctor --probe-entry` 根据 cookie 的 `expires` 自动区分 `persistent/session/mixed/unknown` 并写入 entry 草稿。显式选择 `storage-state` 且探测到 session cookie 时输出凭证快照风险告警。

## 验证证据

- 单元测试：schema 默认值、cookieKind 四分类、daemon 存活/死亡/失效状态、三种策略分支。
- 浏览器实测：Chrome persistent context 登录 Mock OA 后，第二个 Playwright 客户端通过 `connectOverCDP` 读取到同一 session cookie；断开附着客户端后，owner context 仍可继续访问已登录接口。
- `.dsh/` 已加入 `.gitignore`，运行态 PID、CDP endpoint 与状态文件不进入版本库。
