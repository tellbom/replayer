# T-69 表单场景矩阵报告

日期：2026-08-21

## 结论

T-69 放行。G1、G2、G5 由 Playwright 1.62.1 的语义候选稳定命中，结果为 HIGH；G3 与 G4 退化到 `nth`，结果为 LOW。

G3 已确认是通用引擎的结构性盲区：Element Plus 的 label 与 control 没有 `for/id` 或其他可访问性关联时，Playwright 只能得到位置候选。因此 `el-locator.byFormItem` 不能删除，后续必须作为补充候选源进入 pw-generator 候选池或消歧层。

本任务不做 cutover、不修改成本模型、不删除 legacy generator。

## G1-G5 正式录制链路产物

测试入口：`e2e/t69-form-controls.spec.ts`

| 场景 | no-id/关联形态 | 录制产物原文 | confidence | 判定 |
|---|---|---|---|---|
| G1 | 显式 `label for` 关联 textarea | `{"strategy":"playwright","selector":"internal:role=textbox[name=\"事由G1\"i]","confidence":"HIGH"}` | HIGH | 可放行。1.62.1 的 role+accessible-name 分数高于 label 候选，语义等价且唯一。 |
| G2 | 仅 placeholder 的 input | `{"strategy":"playwright","selector":"internal:role=textbox[name=\"请输入事由G2\"i]","confidence":"HIGH"}` | HIGH | 可放行。placeholder 进入 accessible name 后，role 候选优先于 attr 候选。 |
| G3 | Element Plus label/control 无 `for/id` | `{"strategy":"playwright","selector":"internal:role=textbox >> nth=5","confidence":"LOW"}` | LOW | 不可单靠通用引擎；需要 `el-locator.byFormItem` 补充候选。 |
| G4 | 两个 section 内同名“开始时间” | `{"strategy":"playwright","selector":"internal:role=textbox[name=\"开始时间\"i] >> nth=1","confidence":"LOW"}` | LOW | 需由 T-71 的 scope 消除位置依赖。 |
| G5 | radio group 内具名选项 | `{"strategy":"playwright","selector":"internal:role=radio[name=\"同意G5\"i]","confidence":"HIGH"}` | HIGH | role+name 唯一命中。 |

交接文档中 G1/G2 的“期望锚点”描述的是候选来源，不是 Playwright 1.62.1 最终一定输出的引擎名。实际生成器按分数选择 role+name；这不改变 G1/G2 的稳定语义结论。

## `internal:label` / `internal:attr` 接桩验证

适配层现已使用 vendored Playwright 的 attribute parser/matcher、label 提取与文本匹配语义执行这两个内部引擎。为了排除 role 候选的分数优先级干扰，测试使用无可用 role 的控件直接验证引擎查询路径：

```text
label={"selector":"internal:label=\"输出标签\"i","unique":true,"matchCount":1,"confidence":"HIGH","source":"playwright"}
attr={"selector":"internal:attr=[title=\"属性标题\"i]","unique":true,"matchCount":1,"confidence":"HIGH","source":"playwright"}
```

两条候选均由生成器产生、经适配层查询并唯一回指原元素，不是只验证字符串解析。
